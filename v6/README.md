# ROOSA V6

V6 preserves V5's finished photographic homepage and adds the corrected connected-roll
animation as one restrained, scroll-driven chapter immediately after the hero. It is a
self-contained copy: earlier versions are never read from at runtime and never written
to.

```bash
npm --prefix v6 run dev      # http://localhost:3005
npm --prefix v6 run build
npm --prefix v6 run start -- -p 3005  # production server on http://localhost:3005
npm --prefix v6 run prepare:v6  # rebuild public/v6-home from V6's preserved V5 copy
```

## How the routes are built

`/` and `/en` serve `public/v6-home/index.html`, generated from the preserved
`public/v5-home/index.html` by `scripts/prepare-v6-home.mjs`. The generator only inserts
the V6 animation chapter; it does not rewrite V5. `/en/shop`, `/en/product/*` and
`/en/cart` remain static HTML served through `src/proxy.ts`. Everything else
(`/en/impact`, `/en/about`, `/en/journal`, …) is rendered by the Next.js app.

The hero uses 140 desktop frames and 94 mobile frames from
`public/media/toilet-scroll/v2`. Scroll position maps directly to frame number, while
reduced-motion and constrained-data connections receive a single static fallback.

The static HTML is generated by a chain of scripts, each one layering on the previous:

```
public/givewell  →  v2-*  →  v3-*  →  v4-*  →  v5-*
                                              ▲
                          scripts/prepare-v5-static.mjs
```

`prepare-v5-static.mjs` copies `public/v4-*` and layers the V5 corrections on top.
It never edits the V4 output, so re-running it always rebuilds from a clean V4 base.
Each markup patch is a `replaceOnce` with a contract check — if an upstream script
changes the markup, the build fails loudly instead of silently skipping a fix.

## What V5 changes

**Hero composition.** V4 split the hero into a two-column grid, which stranded the lead
paragraph and buttons in a narrow right-hand column (≈10ch at tablet, with the two
buttons overlapping) and rendered white copy over the brightest part of the photograph.
V5 uses one left-aligned editorial column with a paper scrim behind it, so the graphite
copy holds contrast across the frame. The template pins `white-space: nowrap` on the
headline, which clipped the second line inside the reveal mask — V5 unpins it and sizes
the type to fit at every breakpoint.

**Image proportions.** The photography ships in three native ratios — 4:5 editorial
portraits, 3:2 editorial landscapes and 1:1 packshots/cut-outs — but every frame used a
single ratio, so pack artwork was cropped off at both edges. V5 gives the product grid
one 4:5 frame for rhythm and re-fits the square packshots with `contain` over a tinted
backdrop. Only `<img>` tags inside a product frame are re-fitted; the same files are
used as full-bleed textures elsewhere.

**Vision collage.** The image groups had a 595px min-content inside a 460px grid track,
so the outer columns bled off both viewport edges. Every frame is now fluid with a fixed
ratio. The overlay headline gained a scrim it can actually be read against. On a phone
the flanking columns were only ~92px wide — face crops sliding off both edges — so V5
hides them there and centres a single frame for the pinned reveal instead.

**Contrast fixes.** The footer wordmark, body copy, legal links and credit line all
inherited graphite from the light theme and rendered near-black on the dark footer
gradient. The closing CTA headline sat under scattered draggable cut-outs; it now has a
paper halo (pointer-transparent, so the cut-outs stay draggable).

**Mobile flow.** Hero copy is anchored to the lower third over a cream scrim with inline
buttons instead of two full-width stacked blocks. The compact product rows no longer let
price and button collide. The mission tagline moved out of the middle of the heading onto
its own line. Team heading thumbnails were 104×52 slivers and are now legible 3:2 chips.

**Commerce rhythm.** Shop, product and cart ran a flat 144px section padding, a 130px
margin under the page heading and a 100px gap above the product description, regardless
of how much content each block held — and every shop card reserved a 550px box for about
460px of content, then added a 76px margin, so the grid ended in a band of empty space.
V5 replaces the fixed values with content-proportional clamps; the shop page drops from
2917px to 2638px without losing any air. The packshot on the product page already carries
generous margins inside the JPEG, so its frame padding is near-zero. The fixed cart
control is a pill with a shadow, which reads as deliberate when it passes over content.

These rules are scoped to a `[data-v5-commerce]` marker on the commerce `<body>` tags,
because `.section`, `.fact` and `.page-heading` are generic names that also appear on the
home page with different meanings.

**One impact colour.** The two halves of the site disagreed: the static routes set
`--roosa-impact` to a forest green (`#204f45`, residue from the source themes) while the
React routes set `--color-impact` to plum (`#6f294e`). Everything is plum now — a
darkened cousin of ROOSA pink, so the dark bands stay in the warm pink/graphite/paper
family instead of introducing a cool, blue-leaning hue.

**Journal photography.** The first migration pulled the three journal photographs at
WordPress's generated `-388x449` thumbnail crop. The article hero renders about
1354x920, so Next/Image was asked for a 1920px variant and could only return the
source's own ~390px — a 9.3x upscale. `scripts/fetch-journal-originals.mjs` re-fetches
the same files without the generated-size suffix, which is where WordPress keeps the
1200x742 original. The card and hero frames now use the photographs' native ratio so
`object-fit: cover` neither crops the subject nor scales the source up, and `sizes`
accounts for the 2-column tablet breakpoint. Worst-case upscale across seven viewport
widths is now 1.0x.

Article pages previously showed a generic pink-roll thumbnail in the hero panel *and*
their own photograph below it. `PageHero` now accepts `image={null}` for pages that carry
their own full-bleed image, and the panel shrinks to fit its copy. Article subheads ran at
landing-page scale (up to 5.6rem) against a 1.5rem body, which read as a stack of banners
rather than a story; they are article-scale now.

> If you swap an image without renaming it, clear `.next/dev/cache/images` (Next 16 dev
> keeps the optimizer cache there, **not** `.next/cache/images`) and restart the dev
> server. Otherwise some srcset widths keep serving the old file.

## Migrated content

`scripts/fetch-source-assets.mjs` pulls the full-resolution originals from roosa.net —
journal photography at 1200x742, packshots at 1080x1080, roll details at 2048x2048 —
replacing the `-388x449` and `-768x768` crops the first migration took.

**Journal** (`src/lib/journal.ts`) carries all five published posts with their real
bodies. German is the source language and is reproduced verbatim; English is a working
translation, labelled as such in the UI. French is served the English text with the same
notice. Every article keeps its `sourceUrl` so an editor can diff against the live post.
`safeguarding: true` marks stories naming children or families — currently *Der kleine
Kämpfer* — and renders a notice requiring consent, image rights and a safeguarding review
before publication.

**Careers** (`src/lib/careers.ts`) carries the Telefonverkäufer posting in full, including
the phone-only application process. The site's "Stellen" menu still lists a second role,
**Haustürverkäufer** (menu item 10823 → `?page_id=10687`), but that page returns 404
publicly and `rest_forbidden` via the REST API — it exists unpublished. The title and its
menu position are the only fragments that survive, so the role is carried as `closed`
with **no invented description**; its context paragraph is quoted from the published
Jobs-category post *Voller Einsatz für den guten Zweck*.

## A note on `sizes` and fixed-height frames

Several frames used `min-height` with `object-fit: cover`. When the box is taller than the
source's ratio, the browser scales by *height* — which the `sizes` attribute, a width
hint, cannot describe, so it under-requests and the image is upscaled. The journal article
hero was the worst case at 9.3x. Frames now use `aspect-ratio` matched to their sources
(`.articleImage`, `.heroImage`, `.projectImage`, `.projectMedia`, `.roleMedia`), and the
few genuinely portrait frames over landscape sources declare a `sizes` above 100vw with a
comment explaining why. Worst-case upscale is now 1.0x on the journal and ≤1.1x on the
editorial and commerce routes.

The homepage heroes sit at ~1.2–1.3x. That is source-limited, not a `sizes` bug: those are
generated v4 assets whose files are only 1122–1531px wide, and no higher-resolution
original exists to fetch.

**Motion.** The hero headline used a random per-character opacity flicker; V5 uses a CSS
line-mask reveal, which needs no JavaScript to become readable. Scroll copy started at
`opacity: 0.1` — blank for up to two seconds on light sections — and now starts visible.
A single IntersectionObserver pass handles section reveals, and it adds `.v5-js` to
`<html>` only once it is wired up, so a script failure can never leave content invisible.
The GSAP pin in the vision section is kept as the signature moment. Everything is off
under `prefers-reduced-motion: reduce`.

The React routes get the matching layer via `src/components/ScrollReveal.tsx` and the
`.v5-js` rules at the bottom of `src/app/globals.css`.

## Verifying

```bash
python3 scripts/test-v5-polish.py   
python3 scripts/test-v6-release.py  # run against a V6 server on port 3005
```

The focused interaction check covers the cart drawer, demo checkout, mobile-menu focus
handling and lazy images. The release check adds all representative routes at desktop,
tablet, mobile and 320px widths, plus WCAG, assets, internal links and the demo API.
